# 视频化冥想与晚餐演示设计

## 1. 范围

本次将现有 402 x 874 冥想首页原型升级为一条可控的 Web 演示链路：20 秒冥想、完成击掌、手动领取帐篷、感受反馈、IP 提前备料、演示快进至 17:30、正式烹饪，以及回到初始状态。

本次不实现真实时间调度、浏览器自动播放兜底、菜谱页、晚餐过程记录，也不实现晚餐后完整的力量训练页面。力量训练仅在今日卡片中后移至 19:00。

## 2. 最终素材映射

| 状态 | 源文件 | 项目内建议文件名 | 播放方式 |
| --- | --- | --- | --- |
| 冥想中 | `小马冥想.mp4` | `assets/video-meditation.mp4` | 有声循环，持续 20 秒 |
| 冥想结束 | `小马站姿调整.mp4` | `assets/video-meditation-complete.mp4` | 从头有声播放一次 |
| 晚餐备料 | `图片编辑需求 (1).mp4` | `assets/video-meal-prep.mp4` | 有声循环 |
| 晚餐烹饪 | `图片编辑需求.mp4` | `assets/video-meal-cook.mp4` | 有声循环 |

此前的 `图片编辑需求 (2).mp4` 与 `图片编辑需求 (3).mp4` 不再使用。

所有视频均为 720 x 1280、约 10.08 秒。视频使用 `object-fit: cover` 填满 402 x 874 画布，保持主体居中，并接受左右少量裁切。

## 3. 演示流程

### 3.1 初始推荐

- 保留当前首页冥想推荐结构。
- 今日横向日程使用 7 张卡片：
  - 08:00 补充水分
  - 12:00 营养午餐
  - 15:30 冥想
  - 17:30 健康晚餐
  - 18:30 补充水分
  - 19:00 力量训练
  - 22:30 睡前拉伸
- 冥想为当前任务。

### 3.2 冥想中

- 点击“开始冥想”后仍停留在首页空间，不打开新页面。
- 开始前的信息、任务卡和底部导航按现有方向退场。
- 背景切换为 `video-meditation.mp4` 并有声循环。
- 演示倒计时直接从 `00:20` 开始，不使用真实的 5 分钟时长。
- 计时信息覆盖在视频上，不遮挡小马面部。
- 保留暂停与结束控制。

### 3.3 完成与击掌

- 倒计时归零或用户点击结束后，计时器与控制按钮柔和退场。
- `video-meditation-complete.mp4` 从头完整播放一次。
- 击掌节点触发一次轻震动；完成视频期间不同时显示帐篷或散花。

### 3.4 奖励领取

- 完成视频播完后，截取其最后约 2.5 秒作为站立循环背景。
- 进入循环的同时触发散花，并让装有静心帐篷的透明气泡球体从屏幕上方落下。
- 气泡使用轻微回弹后停在画面右下侧，约 `x: 74% / y: 51%`，避免遮挡小马脸部。
- 散花位于气泡和帐篷之后，不覆盖小马眼睛或帐篷主体。
- 气泡直径使用响应式尺寸，约 `clamp(148px, 43vw, 176px)`。
- 帐篷占气泡宽度约 80%，略微上移。
- “点击领取”位于气泡内部、帐篷下方，使用 400 字重，无外轮廓、无独立底色，并与帐篷保留清晰间距。
- 整个气泡都是点击区域；奖励状态不自动超时。
- 点击后气泡破开，帐篷完成领取，随后进入感受反馈。

### 3.5 感受反馈

- 保留现有三项感受反馈。
- 用户未选择时，5 秒后自动结束反馈。
- 本 Demo 不处理有声自动播放的浏览器权限限制。

### 3.6 晚餐备料

- 反馈结束后，全屏播放 `video-meal-prep.mp4`。
- IP 语义为“替用户提前准备晚餐”，不要求用户立即执行新任务。
- 健康晚餐卡成为当前卡。
- 标题为“晚餐正在准备中”。
- 说明为“17:30 回来看看，今晚吃得轻松一点。”
- 主按钮为带铃铛图标的“17:30 提醒我”。

### 3.7 演示快进与饭点

- Demo 不读取真实时间，也不会自行卡在 17:30。
- 点击“17:30 提醒我”后先显示“提醒已设置”。
- 约 900ms 后，顶部时间快速滚动至 17:30。
- 使用约 600ms 暖光遮罩，将备料视频交叉淡化为 `video-meal-cook.mp4`。
- 标题更新为“晚餐时间到了”。
- 说明更新为“好好吃饭，也是今天恢复计划的一部分。”
- 主按钮更换为带餐具图标的“我开动了”。
- 点击“我开动了”直接回到初始冥想推荐状态，便于重复演示。

## 4. 视频循环

- 冥想视频首尾姿态接近，可直接循环两轮覆盖 20 秒演示。
- 站姿完成视频只完整播放一次；奖励阶段只循环末尾约 2.5 秒。
- 备料和烹饪视频首尾内容不同，每次循环结束使用约 600ms 暖光与轻微模糊遮住跳切，再从首帧继续播放。
- 视频切换不使用硬切，只有重新进入对应状态时可以直接显示该状态的视频。

## 5. 页面布局

- 视频是全屏背景层，不放入卡片或弹窗。
- 文字位于左上安全区，使用轻阴影保证在视频上可读。
- 主操作按钮悬浮于任务卡轨道上方。
- 底部任务卡与导航在备料和饭点状态恢复显示。
- 当前任务卡保持 150px 左右宽度，并使用已确认的 `#FFF18A` 至 `#D4F3FF` 斜对角流体玻璃底。
- 当前晚餐图标使用专属横向尺寸，明显放大并上移；图标区与文字底栏分离，任何状态下不得重叠。
- 其他任务图标也遵循“当前任务放大上移、文字固定底栏”的同一结构。

## 6. 按钮与字体

- 现有黄色和黑色实心操作按钮统一改为略带透明度的描边表面，范围仅包括“开始冥想”、“暂停/继续”和“结束”。
- 黄色按钮使用约 82% 不透明度的主黄色、1px 浅黄色外轮廓、轻微背景模糊与克制阴影；保留深色文字，不再使用厚重的底部压边阴影。
- 黑色按钮使用约 74% 不透明度的深色表面、1px 半透明白色外轮廓与轻微背景模糊；保留白色文字。
- 冥想中的双色分段控制保持一个整体胶囊，外侧有统一轮廓，中间使用半透明分隔线；两个分段不得出现双重边框。
- 按下状态通过轻微缩放、亮度变化与阴影收敛反馈，不使用明显的上下位移。
- “17:30 提醒我”和“我开动了”使用参考图风格的透明玻璃胶囊：白色半透明底、白色 1px 边线、轻磨砂和克制阴影。
- 使用正式铃铛与餐具图标，不使用字符或手绘 SVG。
- 除任务卡外，页面标题、正文、时间、按钮、反馈与导航文字统一使用 `font-weight: 400`。
- 任务卡名称、完成状态和“当前”标记保留原有强调字重，以维持横向日程的扫读效率。
- 文字层级通过字号、位置、颜色和留白建立，不通过继续加粗建立。

## 7. 状态模型

建议状态顺序：

```text
recommendation
  -> active-meditation
  -> meditation-complete
  -> reward-awaiting-claim
  -> reflection
  -> feedback-confirmed
  -> meal-prep
  -> demo-time-shift
  -> meal-time
  -> recommendation
```

关键事件：

- `START`
- `TICK`
- `TOGGLE_PAUSE`
- `END`
- `COMPLETION_VIDEO_ENDED`
- `CLAIM_REWARD`
- `SELECT_MOOD`
- `SKIP_FEEDBACK`
- `SET_MEAL_REMINDER`
- `DEMO_TIME_REACHED`
- `START_MEAL`

视频层作为可复用媒体层实现，状态只负责提供视频源、播放模式、文案与控件。这样后续仍可继续替换或扩展冥想视频，而不重写页面结构。

## 8. 失败与降级

- 视频加载失败时显示对应视频首帧或当前房间背景，文字与操作仍可使用。
- Demo 不处理自动播放权限、真实通知和后台计时。
- `prefers-reduced-motion` 下保留必要状态变化，但取消气泡回弹、散花位移、时间滚动和暖光循环遮罩。
- 点击区域至少 44 x 44px；气泡虽然无按钮外观，但必须保留按钮语义、键盘焦点和可访问名称。

## 9. 测试与验收

- 状态机覆盖 20 秒倒计时、完成视频结束、手动领取、反馈、备料、演示快进、饭点和重置。
- 日程测试覆盖 7 张卡片、17:30 健康晚餐和 19:00 力量训练。
- 视觉契约测试覆盖全局 400 字重例外、晚餐当前卡图标尺寸、气泡内部领取文字、晚餐玻璃按钮，以及黄色/黑色按钮的透明度与轮廓样式。
- 在 402 x 874 与 375 x 812 下验证所有状态。
- 浏览器截图必须确认：
  - 计时器不遮挡小马脸部。
  - 气泡与散花不遮挡小马脸部或帐篷。
  - “点击领取”在气泡内清晰可读。
  - 当前任务图标不与文字重叠。
  - 视频、任务卡、主按钮和底部导航互不遮挡。
- 浏览器流程验证必须完整走通并能通过“我开动了”回到初始状态。

## 10. 后续备案

后续版本可在点击“我开动了”后，将厨房视频退场并回到成长基地房间，让 19:00 力量训练成为当前任务，同时切换为力量训练 IP 状态。本次 Demo 不实现该段流程。
