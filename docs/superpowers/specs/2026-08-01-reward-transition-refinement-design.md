# 冥想首页与帐篷领取转场精简设计

## 目标

在不增加产品功能的前提下，让冥想首页、奖励领取和晚餐任务之间形成连续、安静且适合演示的视觉闭环：初始页保持动态，领取奖励有明确庆祝反馈，领取后不经过感受问卷，直接自然过渡到晚餐准备。

## 范围

- 初始页复用冥想视频前 2 秒作为静音循环背景。
- 所有主场景角色均由视频或视频切片承载，删除大型独立 IP 图片层和资源文件。
- 当前任务卡进一步降低高度，同时保留大图标的视觉优先级。
- 奖励页补足散花效果，并将完成视频的最后 1 秒作为摆手循环。
- 新增领取后的 5 秒落地停留状态。
- 删除冥想感受反馈和反馈确认状态。
- 领取后的晚餐转场采用暖光交叉淡化，底部组件保持连续。

不改变七张日程卡的任务内容、晚餐提醒演示逻辑、饭点视频或“我开动了”重置逻辑。

## IP 载体统一

- 视频成为整个项目中大型 IP 形象的唯一载体。
- 删除 `index.html` 中的 `.character-stage` 和 `.character` 节点。
- 删除 `src/app.js` 中所有角色图片切换逻辑。
- 删除 `src/styles.css` 中所有 `.character`、`.character-stage` 及状态相关定位和动画规则。
- 从项目中物理删除以下资源：
  - `assets/ip-lift.png`
  - `assets/ip-meditate.png`
  - `assets/ip-stretch.png`
  - `assets/ip-walk.png`
- 任务卡小图标、底部导航图标和帐篷资源不属于大型独立 IP 图片，继续保留。
- 现有客厅静态图继续作为视频失败时的背景降级，但不再叠加独立角色图片。

## 状态流程

```text
recommendation
  -> active
  -> completion
  -> reward
  -> reward-settled
  -> meal-prep
  -> demo-time-shift
  -> meal-time
  -> recommendation
```

删除 `reflection` 和 `feedback-confirmed`。`CLAIM_REWARD` 从 `reward` 进入新的 `reward-settled` 状态；该状态在 5 秒后自动进入 `meal-prep`。

## 媒体规则

### 初始页

- `recommendation` 使用 `video-meditation.mp4`。
- 视频静音自动播放，只循环 `0–2s`。
- 首页标题、AI 建议、成长提示、任务卡和导航继续覆盖在视频上，不再显示独立 IP 图片层。
- 点击“开始冥想”后解除静音，将播放位置重置为 `0s`，进入 20 秒正式冥想。
- 如果视频加载或播放失败，隐藏视频并显示现有客厅静态背景。

### 正式冥想

- `active` 使用完整的 `video-meditation.mp4`，允许声音播放。
- 倒计时仍只在视频真正播放后启动；暂停和继续同时控制视频与计时器。

### 击掌与奖励

- `completion` 完整播放一次 `video-meditation-complete.mp4`。
- 完整播放结束后进入 `reward`。
- `reward` 和 `reward-settled` 均循环完成视频最后 `1s`，只保留小马站立摆手片段。
- 循环边界按视频实际时长动态计算为 `duration - 1s`，不写死绝对时间。

### 晚餐

- `meal-prep` 继续使用 `video-meal-prep.mp4`。
- `reward-settled` 到 `meal-prep` 使用现有暖光遮罩进行约 700ms 的交叉淡化。
- 底部任务卡与导航在转场期间不退出、不重新进场。

## 奖励时间线

### 奖励出现

1. 击掌视频结束，切入最后 1 秒摆手循环。
2. 散花和帐篷气泡同步出现。
3. 帐篷气泡从上方落到小马面部右下侧的既定安全位置，并持续悬浮。
4. 用户点击气泡内的“点击领取”。

散花使用现有粒子层，但必须在每次进入 `reward` 时重新触发，不能因重复演示或状态复用而缺失。减少动态效果开启时，散花隐藏，帐篷直接出现在稳定位置。

### 领取后 5 秒

以用户点击领取完成为 `0s`：

- `0–0.5s`：气泡收束，帐篷从半空落到房间地面。
- `0s`：显示“静心帐篷已放入营地”。
- `1.5s`：短提示淡出；底部任务卡和导航同时滑入。
- `1.5s`：晚餐卡成为当前任务，已完成的冥想卡转为灰调完成状态。
- `1.5–5s`：保持“小马摆手循环 + 地面帐篷 + 底部组件”。
- `5s`：暖光遮罩淡入，背景切换到晚餐准备视频，再淡出遮罩。

`reward-settled` 期间不显示感受按钮，也不接受反馈输入。

## 任务卡尺寸

- 任务轨道高度：`108px -> 102px`
- 普通任务卡高度：`76px -> 72px`
- 当前任务卡高度：`96px -> 90px`
- 同步收紧卡片上下内边距与网格行高。
- 当前任务大图标保持现有尺寸；只调整可用网格空间和位移，避免图标覆盖时间或标题。
- 卡片宽度、横向间距、磨砂材质、当前卡渐变和完成态灰调保持不变。

## 状态与计时器实现边界

- 状态机只描述业务状态和 5 秒完成事件，不直接操作 DOM。
- 媒体配置负责每个状态的视频源、静音策略和循环区间。
- 页面控制器负责：2 秒/1 秒分段回放、领取动画计时、1.5 秒组件出现、5 秒晚餐切换及遮罩移除。
- 进入其他状态或重置演示时，必须清理领取提示、组件出现和晚餐切换计时器，避免重复触发。

## 无障碍与降级

- 静音首页不依赖声音传递信息。
- 点击开始后才解除静音，符合浏览器媒体播放限制。
- `prefers-reduced-motion` 下取消散花、落体和滑入动画，但保留相同状态顺序；提示与 5 秒停留仍存在。
- 视频失败时沿用静态客厅背景，按钮和日程仍可操作。
- 视频失败时不恢复独立 IP 图片，避免重新引入双重角色体系。
- 领取按钮保留键盘焦点和可读的无障碍名称。

## 测试与验收

### 自动化测试

- `recommendation` 映射到冥想视频、静音并使用 `0–2s` 循环。
- `active` 解除静音并从 `0s` 开始。
- `reward` 和 `reward-settled` 使用最后 `1s` 循环。
- `CLAIM_REWARD` 直接进入 `reward-settled`，不再产生反馈状态。
- 5 秒完成事件进入 `meal-prep`。
- 源码中不再包含感受反馈文案或反馈按钮。
- HTML、CSS 和 JS 中不再包含大型独立角色层或 `assets/ip-*.png` 引用，四张资源文件不存在。
- 卡片与轨道高度分别为 `72px`、`90px`、`102px`。

### 浏览器验收

在 `402×874` 和 `375×812` 验证：

- 首页视频静音播放并稳定在前 2 秒循环，文字和卡片不遮挡。
- 点击开始后视频从头播放且声音策略切换正确。
- 奖励页每次进入都有散花，帐篷不遮挡小马眼睛。
- 最后 1 秒摆手循环没有明显停顿或黑帧。
- 帐篷落地、1.5 秒提示淡出、底部组件出现和 5 秒晚餐切换按顺序发生。
- 暖光转场结束后遮罩自动移除。
- 页面控制台和媒体错误列表为空。
